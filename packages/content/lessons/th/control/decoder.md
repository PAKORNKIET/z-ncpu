# ตัวถอดรหัสคำสั่ง (Instruction Decoder)

## ชิ้นนี้คืออะไร

คำสั่ง Z8 ยาว 16 บิต สองบิตบนคือ **group** ตามด้วย **func** 3 บิต, **rd** 2 บิต, **m** 1 บิต และตัวถูกดำเนินการ 8 บิต decoder อ่านแค่ group, func, m และ flags (z, c, n) แล้วตอบว่า **จังหวะนี้แต่ละส่วนของ CPU ต้องทำอะไร** สายพวกนี้เรียกว่า **สัญญาณควบคุม**

| ขาออก | ความหมาย | เป็น 1 (หรือค่านี้) เมื่อ |
| --- | --- | --- |
| alu_op (3) | งานของ ALU | = func เสมอ |
| reg_write | เขียน register rd | MOV, LOAD, POP, คำสั่ง ALU ทุกตัวยกเว้น CMP |
| flag_write | เขียน flags | คำสั่งกลุ่ม 01 ทุกตัว |
| mem_write | เขียน RAM / I/O | STORE, PUSH, CALL |
| src_sel | src มาจากค่าคงที่ | = m |
| wb_sel (2) | ค่าที่เขียนลง rd | 0 = ผล ALU, 1 = RAM (LOAD, POP), 2 = src (MOV) |
| addr_sel (2) | address ของ RAM | 0 = src, 1 = SP (POP, RET), 2 = SP − 1 (PUSH, CALL) |
| sp_op (2) | SP ถัดไป | 0 = เท่าเดิม, 1 = ลด (PUSH, CALL), 2 = เพิ่ม (POP, RET) |
| pc_sel (2) | PC ถัดไป | 0 = PC + 1, 1 = src (กระโดด), 2 = ค่าจาก RAM (RET) |
| mem_src | ข้อมูลที่เขียน RAM | 0 = rd, 1 = PC + 1 (CALL) |
| halt | หยุด | HALT |

คำสั่งกระโดดแบบมีเงื่อนไขให้ pc_sel = 1 เฉพาะเมื่อเงื่อนไขจริง เช่น JZ ต้อง z = 1 ถ้าไม่จริงก็ไปคำสั่งถัดไปตามปกติ (pc_sel = 0)

คำสั่งที่ไม่ได้ใช้ (กลุ่ม 11 หรือ func ที่ว่าง) ให้ทุกสัญญาณเป็น 0 ซึ่งทำงานเหมือน NOP ส่วน alu_op ยังเป็น func เหมือนเดิม

## ในคอมพิวเตอร์จริง

decoder คือ "สมอง" ของ CPU ที่แปลงตัวเลขเป็นการกระทำ CPU จริงอย่าง x86 มีคำสั่งเป็นพันแบบ decoder จึงซับซ้อนมาก บางรุ่นใช้ ROM ขนาดเล็ก (microcode) แทนวงจรตรรกะ แต่หลักการเหมือนกัน: อ่านรหัสคำสั่งแล้วเปิดปิดสวิตช์ทั่วทั้งชิป
