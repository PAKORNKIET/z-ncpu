# ประกอบ CPU Z8

## ถึงเวลาแล้ว

ทุกชิ้นที่สร้างมาตั้งแต่ NAND ตัวแรกมารวมกันที่นี่ CPU Z8 ทำ **1 คำสั่งต่อ 1 จังหวะนาฬิกา** (single-cycle) ในหนึ่งจังหวะสัญญาณไหลแบบนี้

1. **Fetch** — PC ชี้ address ใน ROM256 ได้คำสั่ง 16 บิต (โปรแกรมมาจากแผงที่ต่อเข้าขา `prog`)
2. **Decode** — แยกคำสั่งเป็น group, func, rd, m และตัวถูกดำเนินการ แล้ว Decoder สร้างสัญญาณควบคุม
3. **Read** — Register file อ่าน rd ออกทาง x และ rs (บิต 0–1 ของตัวถูกดำเนินการ) ออกทาง y แล้ว MUX เลือก src เป็น y หรือค่าคงที่ 8 บิต
4. **Execute** — ALU คำนวณ x กับ src ได้ผลและ flags
5. **Memory** — address มาจาก src, SP หรือ SP − 1 ถ้า ≥ 0xF0 คือ I/O ไม่ใช่ RAM
6. **Write back** — ตอนขอบขาขึ้นของ clock ทุก register (rd, flags, RAM, SP, PC) รับค่าใหม่พร้อมกัน

## ขาของ CPU

| ขา | ทาง | ใช้ทำอะไร |
| --- | --- | --- |
| prog (4,096) | เข้า | โปรแกรม 256 คำสั่ง ต่อเข้า data ของ ROM256 |
| reset, clk | เข้า | reset: A–D = 0, SP = 0xF0, PC = 0, flags = 0 |
| sw, btn, key | เข้า | ค่าที่อ่านได้จาก 0xF8, 0xF9, 0xFA |
| out, leds | ออก | Register ที่เขียนด้วย STORE ที่ 0xF0 และ 0xF1 |
| seg (7) | ออก | Register ที่ 0xF2 ผ่านชิ้น 7-segment ของบท 6 |
| pc, a, b, c, d, sp | ออก | **ขาดีบัก** ต่อค่าใน register ออกมาให้ตรวจ |
| flags (3) | ออก | บิต 2 = Z, บิต 1 = C, บิต 0 = N |
| halt | ออก | คำสั่งที่ PC ชี้อยู่คือ HALT |

## ทดสอบอย่างไร

เกมใส่โปรแกรมทดสอบลงแผง กด reset แล้วเดินนาฬิกาทีละจังหวะ เทียบทุกขาดีบักกับ **emulator** (CPU จำลองที่เขียนด้วยโค้ด) ทุก cycle ถ้าไม่ตรง จะบอกว่าผิดที่ cycle ไหน หลังคำสั่งอะไร และขาไหนได้ค่าผิด ส่วน out, leds, seg เริ่มตรวจหลังโปรแกรมเขียนค่าครั้งแรก register ของ I/O จึงไม่ต้องต่อ reset

ลองเล่นก่อนทดสอบได้: แผงมีโปรแกรมนับ 0–9 ใส่ไว้แล้ว กด **reset CPU** แล้วเดินนาฬิกาดูตัวเลขบนจอ

## ในคอมพิวเตอร์จริง

CPU จริงทำงานตามขั้นเดียวกันนี้ แต่แบ่งเป็นหลายจังหวะซ้อนกัน (pipeline) เพื่อให้นาฬิกาเร็วขึ้น CPU ในมือถือทำหลายพันล้านจังหวะต่อวินาที และมีทรานซิสเตอร์หลายพันล้านตัว แต่หลักการก็ยังเป็น fetch → decode → execute แบบที่เพิ่งต่อเอง
